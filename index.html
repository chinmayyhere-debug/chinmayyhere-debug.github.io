About

My path into AI engineering isn't the typical one. I spent the last two years inside a bank — investigating 10,000+ fraud cases across 5+ TB of transactional data as a Dispute Analyst, auditing technical controls (SOC 1, SOC 2, ISO 3000) as an IT audit intern, and now translating operational requirements into structured, defensible decisions as an Insolvency Officer, all under real regulatory and policy constraints. Alongside that, I completed a Graduate Certificate in AI & Data Science and a run of Oracle and Google Cloud certifications, and started building AI systems on my own — deliberately in domains close to what I already know (regulatory/compliance documents, operational tooling), and deliberately validated the same way I'd validate an audit finding: with evidence, a labeled test set, and an honest account of what's actually been checked versus what hasn't.

How I Build

These aren't abstract engineering values — they're habits carried over directly from fraud investigation and audit work, where every claim needs a trail back to evidence.

01

Verified, not assumed

Every feature is backed by a labeled test suite, run and re-run after every change — not just written and hoped to work.

02

Honest about limits

Code paths that couldn't be live-tested (missing API keys, blocked networks) are labeled "reviewed, not verified" — never dressed up as proven.

03

Abstain over guess

Systems are designed to decline low-confidence answers rather than produce a plausible-sounding wrong one.

04

Document real bugs

Every project ships a validation report — including the actual bugs found during development, root cause, and fix.

Regulatory Document Q&A

A retrieval-based question-answering system over compliance documents (Customer Due Diligence, Transaction Monitoring, Sanctions Screening) using TF-IDF and cosine similarity — every answer is a cited, exact source passage, with no generative model and no hallucination risk. The document domain isn't arbitrary — it mirrors the regulated financial services environment I work in day-to-day.

Python Information Retrieval scikit-learn RAG Foundations Compliance Domain
  • Abstain-when-uncertain design: declines to answer rather than guessing, validated with negative-control test cases built specifically to check this.
  • Found and fixed a section-numbering bug where document preambles were mis-indexed as "section 1," which risked surfacing generic boilerplate as false-positive matches.
  • Explicitly built as the retrieval foundation for a future embeddings + LLM-generation upgrade — not the finished picture.
